# Paco Morningstar's Witches' Companion: developer handover

Published version: **1.1** (versionCode 10100, moon reminders). The next release is **1.2** (versionCode 10200): face-down drawing, card backs, the deck chooser, and the Marseille and Thoth decks.

Version codes come from the tag: `v1.1` is 10100, `v1.2.3` is 10203. Every new tag must be higher than the last.

Version 1.0 is a fresh start: it has a new app ID and a new signing key. The earlier test versions (3.x–4.x) were a different app on the phone, and testers move their data across with a backup.

This file is everything needed to keep building the app, in any Claude account or by hand. Read it before changing anything.

## What the app is
An offline grimoire for Android and iPhone. It covers:
- herbs, crystals, spells, sigils, oils, incense, tinctures, brews and deities
- tarot: layouts, readings, a journal, statistics, and your own photographed decks
- a live moon tracker, with moon and sabbat reminders
- Learn Witchcraft and Candle Magic lessons

People can send their own entries and decks to friends, print any page, and update with one tap.

## Where it lives (keep all of this exactly as it is)
- **GitHub repository:** https://github.com/PacoGeist/WitchCompanion (public). It holds all the source code (everything except the signing key) and the `docs/` website. Installed apps look here for updates.
- **Download page:** https://pacogeist.github.io/WitchCompanion/, served by GitHub Pages from the `main` branch, `/docs` folder.
- **iPhone / web app:** https://pacogeist.github.io/WitchCompanion/app/
- **Update file:** `docs/version.json`. The Android app reads it from
  `https://raw.githubusercontent.com/PacoGeist/WitchCompanion/main/docs/version.json`.
- **Android download:** each GitHub Release is tagged `v<version>`, with one asset named exactly `WitchcraftCompanion.apk`.

## Two things that must NEVER change
1. **The Android app ID `io.github.pacogeist.witchcompanion`**, set in `android/AndroidManifest.xml`. Android identifies the installed app by this ID, so a different ID would be a different app and every user would have to uninstall and reinstall.
2. **The signing key `android/witchcompanion.keystore`.** Its alias and password are in `android/key.properties`. Android only installs an update signed with the same key, and if it is lost, nobody can ever update again. `build.sh` refuses to build without it and never makes a new one.

The key lives in exactly two kinds of place:
- **Your private backups:** `WitchcraftCompanion-source.zip` (it contains the key and `key.properties`), kept in two private places.
- **The repository's Actions Secrets** (`KEYSTORE_BASE64`, `KEY_ALIAS`, `KEY_PASSWORD`), so GitHub can sign builds. Secrets are encrypted and are not visible in the public repository.

Never commit the key or `key.properties` as files. The repository's `.gitignore` blocks keystores, `key.properties`, APKs and zips. The build also checks the APK's certificate against the key's SHA-256 fingerprint (`ce9d08cc…75c2`, in `.github/workflows/release.yml`) and stops if it doesn't match.

## How updating works for users
- **Android:**
  - The app checks GitHub once a day, or when someone taps **More → Check for Updates** or **Settings → App Updates**.
  - When there's a new version, it shows **Update now**. That downloads the new APK inside the app and hands it to Android's installer. Nobody downloads or opens a file themselves.
  - Android always shows its own confirmation the first time. It also asks once to "allow this app to install updates".
  - After the first in-app update, on Android 12 and newer, the app becomes its own installer, so later updates usually install after the single Update now tap.
  - The Java side lives in `android/src/io/github/pacogeist/witchcompanion/MainActivity.java` (`checkUpdate`, `installUpdate`, PackageInstaller session with `USER_ACTION_NOT_REQUIRED`). The page side is `www/js/update.js`.
- **iPhone / web:**
  - The service worker (`docs/app/sw.js`, generated by `build_site.py`) downloads each new version in the background when the app opens online.
  - A "Update ready, Restart now" window then appears. **More → Check for Updates** checks at once.
  - Nothing is downloaded by hand.

## Drawing a reading and card backs
- `#/reading/<spread>` (in `journal.js`) has three steps: **Before You Draw** (spread, positions, question, deck in use), then the cards face down, then the full reading.
  - **Draw & reveal:** one tap (or the Reveal button) turns every card.
  - **Walk through:** each tap turns one card and adds its interpretation and guide prompt below the spread.
  - The reading is saved to the Journal as soon as the cards are dealt, and `?r=<id>` in the address reopens it fully turned.
- `layoutHTML()` in `views.js` draws a face-down card when its entry has `down: true`.
- **Card backs:** `cardBack()` in `deck-photos.js` returns the chosen deck's photographed back (`deck.back`, one photo per deck) or `DEFAULT_BACK`, the app's own SVG design (symmetrical, so it looks the same either way up). Photograph the back from the deck page (**add back** beside the cover); a new deck's photo session starts with the back. Backs travel with backups and shared deck files.
- **My Decks** starts with **Deck used in the app**: Rider–Waite–Smith or any of the person's decks (`settings.activeDeck`).

## Built-in decks: Rider–Waite–Smith, Tarot de Marseille, Thoth
- `www/js/tarot-systems.js` defines `SYSTEMS` (rws, marseille, thoth): each deck's card titles, pictures, back, meanings and symbols. Every card keeps its Rider–Waite–Smith name as its identity (the Journal and Card Stats use it); `cardTitle(name, sys)`, `cardImg(name, sys)`, `meaningsFor(sys)` and `symbolsFor(sys)` give the deck's version.
- `settings.activeDeck` is `''` (Rider–Waite–Smith), `sys:marseille`, `sys:thoth`, or the id of a person's deck. A person's deck has `system` (which deck's names and meanings it follows). `activeSystemId()` works it out. Each reading stores `system`; older readings count as `rws`.
- **Marseille pictures:** `www/img/tarot-marseille/<code>.jpg` (codes as in `img/tarot/`, plus `back.jpg`). They come from the public-domain BnF scans listed in `data/marseille-sources.json` and are downloaded once by the **Fetch Marseille pictures** GitHub workflow (`tools/fetch_marseille.py`). Marseille numbering: Justice VIII, Strength XI; suits Batons, Cups, Swords, Coins; Valet for Page.
- **Thoth:** the Harris paintings are under copyright, so cards show title faces drawn in code (`thothFace()`). Thoth numbering: Adjustment VIII, Lust XI; Disks for Pentacles; courts Princess = Page, Prince = Knight, Queen, Knight = King. People can photograph their own Thoth deck in My Decks.
- **Text:** `data/tarot-meanings-marseille-N.json`, `data/tarot-symbols-marseille-N.json` and the same for `thoth`, bundled by `build_data.js` into `MARSEILLE_MEANINGS` etc. Same fields as Rider–Waite–Smith, plus `title`. Check them with `python3 tools/check_deck_text.py marseille` (or `thoth`). The minor-card symbol files are generated by `tools/make_marseille_minor_symbols.py` and `tools/make_thoth_minor_symbols.py`.
- Card by Card (`#/deck?d=<deck>`) and card pages (`#/card/<name>?d=<deck>`) have a deck selector.

## Moon reminders
- **Moon Tracker → Remind me**, or **Settings → Moon reminders**, opens `#/moon/reminders`. Choices are saved in `settings.reminders` (`on`, `phases`, `sabbats`, `when` = `day`/`before`/`both`, `time` = `HH:MM`) and travel with backups.
- **Android:** `www/js/reminders.js` works out about 400 days of reminders with `moon.js` and passes them to `AndroidBridge.setReminders` on every app start, every settings change and every backup import. `ReminderReceiver.java` keeps the list and sets one alarm at a time with `AlarmManager.setAndAllowWhileIdle` (no exact-alarm permission, so a reminder can arrive a few minutes late). It sets the alarm again after a restart, an app update or a clock change. Tapping a notification opens the Moon Tracker. Android 13+ asks once to allow notifications.
- **iPhone / web:** a web app can't wake itself up offline, so the same page makes an `.ics` calendar file (all-day events with alerts at the chosen time, twelve months ahead) and the phone's calendar does the reminding.
- Notifications use no network. The status bar icon is `android/res/drawable/ic_stat_moon.xml`.

## Releasing a new version
GitHub builds and publishes every release by itself (`.github/workflows/release.yml`).
1. Change the code. Put the "what's new" lines in `notes` in `release.json` (the version numbers there are only used for local builds).
2. In GitHub Desktop, commit and **Push origin**.
3. Still in GitHub Desktop, open **History**, right-click the newest commit, choose **Create Tag…**, type the new version (for example `v1.2`) and click **Create Tag**. Then click **Push origin** again; it sends the tag.
4. GitHub then, on the repository's **Actions** tab (about 5 minutes):
   1. works out the version from the tag and refuses a tag that isn't newer than the live one
   2. builds and signs the APK with the key from Secrets, and checks the app ID, the version and the signing certificate
   3. creates the Release `v<version>` with `WitchcraftCompanion.apk` and checks that the download answers
   4. only then rebuilds `docs/` (download page, web app, `version.json`) and pushes it to `main`. That push is what tells installed apps there is an update.
5. If a run fails, nothing reaches users. Read the red step on the Actions tab, fix, and push a new tag (or delete the tag and push it again).

After a release, GitHub has added a commit to `main`, so click **Fetch origin** and **Pull** in GitHub Desktop before the next change.

**Building by hand** (optional, needs the Android SDK and the key files from the zip): `node build_data.js`, `bash android/build.sh` (set `ANDROID_SDK` if the SDK isn't at `/opt/android-sdk`), then `python3 build_site.py`.

`python3 build_preview.py` builds a one-file preview (`preview/index.html`) that can be published as a Claude artifact for testing. That preview is optional and separate from the real app.

## Build requirements
- Node 18 or later, Python 3, and Java 17 or later (`javac` and `keytool`).
- Android SDK `build-tools;35.0.0` and `platforms;android-35` at `/opt/android-sdk`. Install them with Google's command-line tools:
  `sdkmanager --sdk_root=/opt/android-sdk "build-tools;35.0.0" "platforms;android-35"`
- No Gradle. `build.sh` uses aapt2, javac, d8, zipalign and apksigner directly.
- GitHub's build machine installs all of this by itself; you only need it to build on your own computer.
- Tests use Python Playwright with Chromium. Set the browser path at the top of each `test_*.py` if it differs.

## Home screen and bottom bar
- **Settings → Arrange home screen & bottom buttons** opens `#/settings/home`. That page has the home-tile order, show/hide and reset (`settings.homeOrder`, `settings.homeHidden`), and the bottom-bar picker.
- **Bottom bar:** Home is always on the left and Search on the right. The three middle buttons are `settings.tabbar` (default Herbs, Crystals, Moon) and can be any home-screen tile. Picking a tile that is already in another slot swaps the two. `renderTabbar()`, `tabDef()` and `setTab()` live in `core.js`.

## Owner's preferences (follow these)
- **Tarot:**
  - Never use reversed cards.
  - Every spread position has a `guide` prompt.
  - Layout pictures must match the real spread exactly.
  - Holiday and seasonal spreads have themed backdrops.
- **Safety first:**
  - Every herb, crystal, spell, oil, incense, tincture and brew has `caution`, `interactions`, `pets`, `toxic`, `externalOnly` and at least two reputable `sources` (NCCIH, MedlinePlus, MSK About Herbs, Drugs.com, LiverTox, EMA, ASPCA, Poison Control, Tisserand Institute, CDC, PubMed).
  - New spells are harm-free and never target another person's will.
- **Recipes:** every ingredient used in a recipe has its own entry.
- **Photos:**
  - Openly licensed only (CC0, CC BY, CC BY-SA or public domain), and credited.
  - Use the familiar, recognizable produce or plant.
  - Photos the owner supplies are credited "supplied by Patrick".
- **Layout:** nothing may run off the side of any page.
- **Look:** dark purple and gold, with the Cinzel Decorative, Cormorant Garamond and IM Fell English fonts.
- **Writing:** plain American English, with no em dashes in content.
- **Network:** the app stays offline apart from the update check. Moon reminders work entirely on the device.
